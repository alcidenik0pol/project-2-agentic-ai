01 The Problem
Why finding pain points is broken

Founders are flying blind.

Bias
Intuition is shaped by you.
Every founder reasons about the market through the lens of their own experience. The pain you remember is rarely the pain that's most widely felt.
Latency
Desk research is slow.
Scrolling Reddit, Hacker News, and X by hand takes days. Most early-stage teams skip it entirely and rely on gut calls instead.
Hallucination
Model knowledge isn't truth.
Ask any LLM "what are people complaining about in X?" and you'll get confident, fluent, well-structured answers — ungrounded in any real conversation.
The opening
Real complaints already exist — in plain public text. Nobody is structurally listening.

LangGraph StateGraph · 3 nodes

Three agents. One graph. Distinct jobs.

Agent 01
Orchestrator
Tools available
fetch_posts
Interprets the topic, selects subreddits, queries the Reddit API, and returns raw structured posts and comments.
Agent 02
Analyst
Tools available
classify_posts cluster_themes
Tags every post {theme, is_complaint, intensity}, filters out non-complaints, then clusters pain points by semantic similarity.
Agent 03
Hypothesis
Tools available
generate_hypotheses save_artifact
Synthesizes five ranked, concrete business ideas from the clusters — each tied to real supporting posts — and persists the report to disk.
Each agent runs an iterative tool-calling loop.  The LLM decides which tool to invoke  — never the backend.

04 Engineering Choices
What's non-obvious

Built to handle hundreds of posts.

Context discipline
A shared store, not the prompt.
Agents pass results through a shared in-memory store — never through LLM context. A 100-post dataset does not enter any prompt window. Tool results that exceed the limit are truncated; full data lives on disk.
Cost optimization
Tiered models.
7 / 8
Calls on Flash tier
Seven of eight LLM calls use Gemini 2.5 Flash — classification, subreddit selection, theme expansion, cluster naming. Only the final synthesis uses Pro, where reasoning earns its cost.
Throughput
Parallel classification.
458s → 49s
LLM work vs. wall time · 100 posts
A ThreadPoolExecutor with 10 workers turns 458 seconds of cumulative LLM calls into roughly 49 seconds of wall time. Measured every run.

05
05 The EDA Engine
Patterns, not paragraphs

The analysis is real EDA, not a summary.

i.
Classify
One LLM call per post extracts {theme, is_complaint, intensity} at temperature 0.1. Ten workers in parallel.
ii.
Filter
Defense in depth: non-complaints are removed at the tool boundary and again inside the clusterer. Kept on disk for transparency.
iii.
Embed
Short themes are expanded into 10–20 word descriptions (batched, cached 24h), then embedded with text-embedding-004.
iv.
Cluster
KMeans across K = 8…15, scored by silhouette. The K with the best score wins. No hardcoded cluster count.
v.
Name
A per-cluster LLM call produces a 3–5 word label, post count, and total upvote weight for the synthesis stage.
