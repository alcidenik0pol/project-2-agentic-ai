Tool fetch_posts — route to data source, scrape, store app/agents/tools/fetch.py:71 ▶

DECISION 1 — data source router branches on get_data_source():

  • v2reddit_v2 — HTML scraper on old.reddit.com. Default for live data. Expanded below.
  • reddit_live — legacy JSON client. Currently broken (Reddit returns 403 on .json); kept for the rate-limit singleton interface.
  • pushshift — DuckDB SQL over local HuggingFace Parquet (fddemarco/pushshift-reddit).
  • linanqiu — local JSON, in-memory keyword filter.
  • sample_* — static file load, no filtering.
  • else → returns {"error": "Unknown data_source"}

Reddit API v2 — why it exists: Reddit killed the public .json endpoints (now 403). v2 scrapes https://old.reddit.com HTML, which still returns 200.

Files: app/reddit_v2/redditapiv2_client.py (HTTP + rate limiting), redditapiv2_parser.py (BeautifulSoup parsing), redditapiv2_fetcher.py (orchestration).

  • if use_llm_selection=True → select_subreddits_with_llm(topic, max)
    • Loads ≤60 curated subreddits from data/subreddit_descriptions_*.json
    • Prompt asks LLM to pick the most relevant for the topic
    • DECISION 2 — fallback: empty response, JSON parse fail, any exception, or empty list → _fallback_selection() keyword scoring

Sub-step B — Per-subreddit fetch loop (caps at 100 posts total)

  • CANCEL CHECK — if is_cancelled(): raise PipelineCancelled() before each subreddit & each post

    • distinguished (mod/admin) → skip

Handoff Shared store — bulk data does NOT travel through LLM context app/agents/tools/shared.py:12 ▶

A module-level dict _shared_data is the canonical channel between tools. LLM context only carries a short message telling each agent what is available — never the posts themselves. This avoids MALFORMED_FUNCTION_CALL errors from oversized JSON.

Orchestrator → Analyst context message includes a soft guard:

  • "If the fetch returned an error or 0 posts, do NOT call classify_posts — there is nothing to analyze; state that clearly and stop. Otherwise proceed."

Also carries a threading.Event as cancel_event for cooperative cancellation propagation.

Tool cluster_themes — embed, KMeans, name clusters app/agents/tools/cluster.py:42 · clustering.py:40 ▶

Guards:

  • if no classified_posts → error
  • if no complaint posts with themes → {"error": "No classified posts with themes found"}

7-step internal pipeline:

  1. Extract themes — build theme_to_count and theme_to_posts from classified posts
  2. Canonicalize — ThemePreprocessor.deduplicate_themes() with SequenceMatcher @ threshold 0.95
  3. DECISION 7 — if canonical_count == 1 → single-cluster shortcut, skip KMeans entirely
  4. Expand themes LLM #5 — batched call to expand short labels into 10–20 word descriptions (3 retries with strengthened prompt; final fallback = theme + first post title)
  5. Embed — provider.get_embeddings() (text-embedding-004 or gemini-embedding-2-preview)
  6. DECISION 8 — pick k if silhouette enabled AND min_k ≠ max_k → iterate k ∈ [8, 15], pick highest silhouette; else use min_k. Then fit KMeans(n_init=10).
  7. Name clusters LLM #6 — per-cluster 3–5 word name. DECISION 9 — retry chain: bad name (ends &, ,, or < 5 chars) → strengthened prompt → first-theme fallback

Side effects:

  • store["clustered_data"] ← clusters + posts (each post annotated with cluster_id)
  • save_clustering_eda()

Steps:

  2. LLM call #7 generate_hypotheses — renders HYPOTHESIS_PROMPT with {clusters_json} and {user_query}; generate_structured(temperature=0.3, max_tokens=16384)

Error & cancel paths

5 distinct failure modes — all cooperative
Error LLM call failure → swallowed as error response graph.py:156 ▶

provider.chat_with_tools raises → _run_agent_loop catches and returns {"response": "Error: LLM call failed after retries - …"}. Agent halts gracefully.

Error Tool exception → JSON error response tools/__init__.py:74 ▶

execute_tool swallows generic exceptions and returns {"error": &hellip} JSON back to the agent loop — the LLM can decide to retry or stop. But PipelineCancelled is re-raised (line 70) so it propagates.

Cancel PipelineCancelled → propagate, delete partial run dir analysis_service.py:242 ▶

User clicks cancel → request_cancel() sets cancel_event → fetcher polls is_cancelled() → raises PipelineCancelled → bubbles through execute_tool → caught at _run_in_thread → status="failed", partial run directory deleted via shutil.rmtree, WS analysis_cancelled sent.

Error Rate-limit detection → user-friendly message analysis_service.py:382 ▶

Generic pipeline exceptions are inspected for keywords "429", "rate", "too many requests" → re-raised with a user-friendly message. Writes a FAILED report.md.

Error Soft guards — empty data stops the pipeline cleanly graph.py:240 · :247 ▶

When fetch_posts returns status: "no_results" or an error, the analyst/hypothesis agents receive context messages instructing them not to invoke their tools. They state the situation clearly and stop. No exceptions, no wasted LLM calls.
